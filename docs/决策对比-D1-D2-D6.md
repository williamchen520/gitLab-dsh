## D-1 分叉语义：轻分支 vs 派生子实验

### 本质问题

> 一个「实验」到底指**一个课题**，还是**一次尝试**？

这个问题的答案直接决定分叉放在哪一层。选轻分支，等于说「一个实验可以有多条版本线」；选派生子实验，等于说「每条线都是独立的实验」。

### 方案 A：轻分支（纯指针）

```text
Experiment E
 ├── branch main    → S1 → S2 → S3
 └── branch alt     → S1 → S2' → S3'
```

从快照 `S1` 派生时，只往 `branch` 表插一行，指向 `S1`。两条线共享同一个 `experiment` 实体。

**带来的影响：**

| 维度 | 结果 |
|---|---|
| 数据模型 | 只多一张 `branch` 表，`experiment` 表不动 |
| 实现成本 | 低，约半天；本质是「指针 + 切换」 |
| 切换体验 | 可以在两条线之间来回切换，像 `git checkout` |
| 对比 | 任意两个快照直接 diff，天然支持 |
| 元数据 | **两条线共享同一份标题/假设/参数**，无法各自不同 |
| 导出 | 导出「实验 E」时，导哪条线？需要额外选分支 |
| 统计 | 同实验下所有 run 混在一起，实验级指标容易串味 |

**最典型的失败场景**：做对照组/实验组。A 方案下两者是同一实验的两条分支，但对照组和实验组的**假设和参数本来就不同**，硬塞进一个 `experiment` 行，要么字段冗余，要么只能写进快照消息里——信息降级。

### 方案 B：派生子实验

```text
Experiment E1（基线）
   └── S1 ──derived_from──> Experiment E2（对照组）
                              └── S2 → S3
```

派生时新建一行 `experiment`，`derived_from_snapshot_id` 指向 `S1`。`E2` 有自己的标题、假设、参数、状态。

**带来的影响：**

| 维度 | 结果 |
|---|---|
| 数据模型 | `experiment` 加一个 `derived_from_snapshot_id` 字段，无 `branch` 表 |
| 实现成本 | 中；需要「派生时只建指针、不复制 blob」的逻辑 |
| 切换体验 | **不能来回切**，派生后各走各的 |
| 对比 | 跨实验 diff，需先经 `derived_from` 找到共同基线，多一跳 |
| 元数据 | 每个实验独立，干净 |
| 导出 | 每个实验可独立导出、独立引用、独立发表 |
| 统计 | 实验级指标天然隔离 |
| 来源追踪 | 派生链可能变深，需要树状视图 |

**注意一个坑**：派生时如果复制了产物文件，磁盘会翻倍。必须保证派生只创建指向**同一 CAS 对象**的新 `snapshot_item`，零拷贝。

### 对比总结

| | A 轻分支 | B 派生子实验 |
|---|---|---|
| 心智模型 | 一个实验，多条线 | 一次尝试，一个实验 |
| 实现成本 | 低 | 中 |
| 元数据隔离 | 差 | 好 |
| 来回切换 | 支持 | 不支持 |
| 对照组场景 | 别扭 | 自然 |
| 报告/导出 | 需选分支 | 直接导 |
| UI 复杂度 | 高（分支切换器） | 低（实验列表） |

### 建议

**选 B。** 理由：实验记录的读者是「三个月后的自己」和「合作者」，他们问的是"这个实验做了什么"，不是"这个分支怎么来的"。B 让每个实验自解释，A 把解释权交给了分支名。

**反悔成本**：A → B 容易（加字段 + 迁移脚本）；B → A 难（已有实验都是独立实体，合并回一个多分支实验需要重构）。所以先选 B 更安全。

**什么情况下改选 A**：如果你们的真实工作流是「同一个实验，参数扫描十几组，最后选一组写报告」——这种"同课题多线并行"的场景，A 的切换成本更低。但注意：参数扫描本质是 `Run` 而非 `Branch`，B 用「一个实验 + N 个 run」也能表达。

## D-2 大文件：内容寻址还是引用

### 本质问题

> 一份 500MB 的原始数据，在快照里应当**存一份副本**，还是**只存一个指针**？

这直接触及系统最核心的承诺——快照不可变、可复现。引用策略是唯一会在这条承诺上开口子的地方。

### 三种口径

| 口径 | 行为 | 磁盘 | 提交耗时 | 可复现性 |
|---|---|---|---|---|
| **A 全量寻址**（不设限） | 所有文件都复制进 CAS，按哈希去重 | 每次改动产生新副本 | 每文件算一次 SHA-256 | ✅ 强保证 |
| **B 阈值 256MB** | 超过阈值只存引用 | 省 | 快 | ⚠️ 有失效风险 |
| **C 阈值 1GB** | 同上，但触发更少 | 中等 | 中等 | ⚠️ 触发少但一旦失效影响大 |

### 量化对比

假设一份 500MB 原始数据，实验期间修改并提交 10 次：

| 口径 | 占用（估算） | 说明 |
|---|---|---|
| A 全量 | ~5 GB | 每次提交一份新副本；**但配合硬链接/块克隆可降到 ~500MB** |
| B 256MB | ~500 MB | 只存一份引用 |
| C 1GB | ~5 GB | 未达阈值，退回 A 的行为 |

关键发现：**A 配硬链接可以同时拿到"强保证"和"低占用"**——只要文件没被原地修改，硬链接共享同一份磁盘块。NTFS 支持硬链接（同卷），ReFS 支持块克隆。代价是唯一一次真正的复制发生在内容变化时。

### 引用策略的致命问题

选 B 意味着快照里存的是一条「在 `D:\data\raw.h5`」的记录。如果用户之后：

- 移动或重命名了文件 → 引用失效
- 用别的软件原地覆盖了内容 → 快照记录的哈希与磁盘不符，**静默的完整性破坏**
- 删除了文件 → 快照指向虚空

这三种情况下，快照"可复现"的承诺已经不成立，但系统表面看起来一切正常。这是最危险的失败模式——**不是报错，而是给了错误的确定性**。

若仍要选 B，必须配套：

1. 每次打开快照时校验引用可读性与哈希
2. 失效引用在 UI 上显著标红，禁止导出为"完整"
3. 提供「就地固化」按钮，把引用转成真实副本

### 对比总结

| | A 全量寻址 | B 阈值引用 |
|---|---|---|
| 可复现保证 | 强 | 弱（需额外校验） |
| 磁盘占用 | 高（可用硬链接缓解） | 低 |
| 实现复杂度 | 低 | 高（校验、失效态、转固化） |
| 用户心智 | 简单：提交即固化 | 复杂：有的存了有的没存 |

### 建议

**选 A，但加上硬链接去重。** 理由：引用策略把复杂度从"存储层"转移到了"用户心智 + 失效处理"，而后者更难做对。M1 阶段先把正确性做扎实，磁盘问题用硬链接解决，真不够了再引入阈值。

阈值留成配置项（默认关闭），等真实数据量说话。

**反悔成本**：A → B 容易（加阈值判断）；B → A 需要把所有引用转固化，历史快照要重写——**接近不可逆**。

## D-6 快照粒度：整实验 vs 单文件

### 本质问题

> 用户点「保存快照」的时候，封存的是**整个实验的当前状态**，还是**某一个文件**？

### 方案 A：整实验快照

一次提交，把该实验下所有 run / step / artifact 的当前状态固化成一棵完整树。

```text
S3 = { run-1/{step-1..5, data.csv}, run-2/{step-1..3, plot.png} }
```

**影响：**

- 语义清晰："这个实验在 3 月 5 日是这样的"
- diff 天然是整树 diff，能看出"这次加了哪个 run、改了哪个参数"
- 快照数量 = 提交次数，历史粒度粗但可读
- 缺点：只想保存一个图，也要固化全部（但内容寻址让未变部分零成本）

### 方案 B：单对象快照

每个 artifact 独立版本化，提交单位是单个文件或单条记录。

**影响：**

- 粒度细，适合"边做边存"
- **快照数量爆炸**：写 50 个步骤就 50 个快照，DAG 退化成线性长链
- 丢失"整体状态"概念——要回答"实验当时是什么样"必须重放整条链
- diff 只能逐对象，跨对象的一致性无法表达
- 实验与运行的边界被抹平，领域模型失去意义

### 方案 C：两级（整实验 + 对象版本链）

整实验快照为主，同时每个 artifact 保留自己的版本链，快照引用对象版本。

**影响：**

- 兼顾两种需求，但**实现复杂度翻倍**
- 概念上需要向用户解释"快照"与"版本"两个东西的区别
- M1 阶段不建议

### 对比总结

| | A 整实验 | B 单对象 | C 两级 |
|---|---|---|---|
| 用户心智 | 简单 | 碎片化 | 需学习 |
| 快照数量 | 可控 | 爆炸 | 可控 |
| 整体状态 | ✅ | ❌ | ✅ |
| 细粒度回滚 | 需整树回滚 | ✅ | ✅ |
| 实现成本 | 低 | 中 | 高 |
| 与 D-1 配合 | 好（派生点=快照） | 差 | 中 |

### 建议

**选 A。** 实验记录的价值在「整体可复现」，不在「单个文件可回滚」。而且内容寻址已经让未变的文件零成本复用，"整实验快照"并不会真的变重。

**反悔成本**：A → C 是增量增强（加对象版本表），不是推翻；A → B 需要改用户流程。所以 A 是安全起点。

## 三者的联动

定完上面三条，数据模型基本就锁死了。联动关系：

```text
D-6 = A（整实验快照）
   └── 快照是全量树 → D-1 的派生点天然是「某个快照」，B 方案直接成立
D-1 = B（派生子实验）
   └── 派生时零拷贝引用同一批 CAS 对象 → 依赖 D-2 的寻址粒度一致
D-2 = A（全量寻址）
   └── 快照里的每条记录都是可校验的哈希，不依赖外部文件状态
```

**推荐组合：D-6=A + D-1=B + D-2=A（硬链接去重）**

这套组合的内部一致性最强：每个快照自包含、可独立校验、派生零成本、无外部依赖。代价是磁盘占用，用硬链接兜住。

### 若选另一套

如果业务上明确需要「同实验多线并行 + 大量大文件」，则 `D-1=A + D-2=B` 更省成本，但要接受：导出时必须选分支、引用可能失效、需要额外的完整性校验层。这是用正确性换成本，属于合理取舍——只是要**显式地**接受它，而不是默认滑进去。
