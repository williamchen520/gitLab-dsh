# 01 · 契约与决策

## 契约是什么

`ARCHITECTURE.json` 是**唯一事实源**：路由、工具、模型、存储、不变量都写在这里，代码要向它对齐，而不是反过来。

主要字段：

```jsonc
{
  "meta":       { "name", "version", "description", "governance" },
  "decisions":  [ { "id", "date", "status", "chosen", "rejected_because", ... } ],
  "invariants": [ "快照创建后内容不可修改", ... ],
  "layers":     { "kernel": {...}, "shells": [...] },
  "models":     { "snapshot": {...}, "item": {...} },
  "mcp":        { "tools": [ ... ] },
  "api":        { "endpoints": [ ... ] },
  "storage":    { "adapters", "metadata_tables", ... },
  "verification": { "unit_and_integration", "contract", ... }
}
```

## 谁能改

```text
AI / 任何自动化：只能提出拟修改 JSON + 原因
人类：回复“批准修改”后，才允许落盘
```

三条硬规则：

1. 没有“批准修改”，**JSON 和实现代码都不得改**；
2. 测试失败若因代码与 JSON 不一致，**改代码**，不许改 JSON 迁就测试；
3. 提交信息必须带 `[APPROVED_BY_HUMAN]`，否则 `commit-msg` 钩子拒绝提交。

## 纯新增例外

已经实现且测试通过、**不改不变量、不改已有语义**的工具或端点，可以随功能同批提交，不必逐条报批。

```text
可以：新增一个工具/端点，并把条目补进 mcp.tools / api.endpoints
不可以：改字段名、改方法、改状态机、删节点
```

## 决策记录

架构级或不可逆的选择，写成 `decisions` 数组里的一条：

```json
{
  "id": "D-7",
  "date": "2026-11-05",
  "status": "accepted",
  "owner": "human",
  "summary": "一句话决定",
  "options": ["A ...", "B ..."],
  "chosen": "B",
  "rejected_because": { "A": "具体到约束，不是偏好" },
  "impact": ["路由", "存储", "兼容性"]
}
```

- `status`：`proposed → accepted → superseded`；
- 至少两个选项，否则不算决策，只是执行；
- 详细论证可以放 `docs/decisions/`，机器可读结论放 JSON；
- **新增/修改决策条目本身也是 JSON 变更**，同样要“批准修改”。

## 会自动生成给人看的部分

```bash
python scripts/render_arch_md.py          # 更新 ARCHITECTURE.md 的契约速查块
python scripts/render_arch_md.py --check  # 不同步则 exit 1
```

`ARCHITECTURE.md` 里 `<!-- BEGIN GENERATED: contract-digest -->` 与 `END` 之间是生成块，**不要手改**。

## 常见问答

**Q：能不能先写代码，事后补 JSON？**
A：纯内部函数可以；只要新增了对外路由/工具，就必须先进契约。

**Q：JSON 改了但校验没过怎么办？**
A：修 JSON 或修代码，不允许跳过校验，也不允许注释掉校验。

**Q：决策记录和 docs 里的设计文档有什么区别？**
A：决策记录是“选了什么、否了什么”，一页以内；设计文档是论证过程，可以很长。
