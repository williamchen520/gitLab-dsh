# 05 · 常见错误

新人最容易踩的十个坑，按出现频率排序。

## 1. 手改生成块

`ARCHITECTURE.md` 里 `BEGIN GENERATED` 与 `END` 之间是脚本生成的，手改下次渲染就没了。

```bash
python scripts/render_arch_md.py   # 改 JSON 后跑这个
```

## 2. 为了跑通测试去改 JSON

契约是裁判，不是被裁判的对象。测试与 JSON 不一致时**改代码**。

## 3. 没拿到“批准修改”就动 JSON

哪怕只改一个字段名，也是变更。先贴拟修改片段，等回复。

## 4. 提交信息漏了标签

JSON staged 时没有 `[APPROVED_BY_HUMAN]`，`commit-msg` 直接 exit 1。补标签再提交，不要 `--no-verify`。

## 5. 追溯矩阵的 test 是编的

`check_traceability.py` 会去文件里找 `def 名字(`。名字对不上 → exit 1。

## 6. `--tests-root` 指错

矩阵在契约仓库，测试在代码仓库。漏了这个参数会报 “test file not found”。

## 7. 计划写了三条，矩阵只有一条

说明有两条没人负责。补齐或从计划里删掉，不要留悬空。

## 8. 只写形状校验，不写语义校验

路由全对、行为全错。新增不变量必须配 `test_inv_*`。

## 9. 决策记录只写“选 B”

没有选项、没有否决理由，三个月后没人知道为什么。至少写两个选项。

## 10. 一个 PR 里混多个主题

功能 + 重构 + 格式化一起提，评审无法判断风险。拆开，一次一件事。

---

## 卡住时怎么办

```text
同一错误出现 2 次以上        → 停下来讨论，不要继续试
需要改不变量/鉴权/数据迁移    → 停下来，等人工判断
超过 300 行净变更            → 标记 [LARGE]，拆或专门评审
不确定某条是否算语义变更      → 按“是”处理，先问
```
