# 开发流程导读（5 分钟版）

这个目录把 `docs/开发流程规范.md` 拆成几份**给人看**的说明。规范本身仍是唯一权威；这里负责讲清楚“为什么”和“怎么做一遍”。

## 一句话

**架构写在 JSON 里，计划写在 Markdown 里，两者用追溯矩阵对账，全部过门禁才允许提交。**

## 一次完整循环（照做即可）

```text
1. 讨论：要改什么，为什么
2. 决策：架构级/不可逆的选择，写进 decisions（需“批准修改”）
3. 契约：改 ARCHITECTURE.json → validate_arch + validate_mcp
4. 计划：docs 里写计划书，列验收条目
5. 追溯：写 plans/<id>.traceability.json，指向契约条目和测试
6. 实现：小步 diff，一条不变量一条测试
7. 门禁：五个命令全过（见 03）
8. 提交：worklog + commit（JSON 变更带 [APPROVED_BY_HUMAN]）
9. 评审：PR Pending Review，等“批准合并”
```

## 三条不能破的线

```text
1. 没收到“批准修改”，不改 ARCHITECTURE.json
2. 没收到“批准合并”，不 merge
3. 校验失败，不改契约迁就测试
```

## 术语表

| 词 | 意思 |
|---|---|
| 契约 | `ARCHITECTURE.json`，机器可读的架构 |
| 形状校验 | 路由/工具清单是否与契约一致 |
| 语义校验 | 不变量是否有可执行断言（如只追加） |
| 追溯矩阵 | 计划条目 ↔ 契约条目 ↔ 测试 的对账表 |
| 门禁 | 一组 exit 0 才算通过的检查命令 |
| 决策记录 | `decisions` 数组里的一条，含选项与否决理由 |
